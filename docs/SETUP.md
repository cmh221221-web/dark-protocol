# DARK PROTOCOL — локальный запуск и статус

В репозитории уже есть существующий Liquid Glass интерфейс с главной, музыкальным экраном, картой Dark Empire, AI, Community и профилем. Он сохранён. Backend добавлен как отдельный слой: запуск сервера показывает исходную страницу и предоставляет Telegram-authenticated REST API.

## Посмотреть интерфейс

Для предпросмотра нужен Node.js 20+:

```bash
npm install
npm start
```

Откройте `http://localhost:3000`. Страница отображается и без Telegram; это визуальный предпросмотр, не авторизованная игровая/социальная сессия. Чтобы проверить Telegram Mini App целиком, задеплойте по HTTPS, задайте URL в настройках Telegram Mini App и настройте сервер по инструкции ниже.

## PostgreSQL и Telegram

1. Создайте PostgreSQL database и скопируйте `.env.example` в `.env`.
2. Задайте `DATABASE_URL`, случайный `JWT_SECRET` длиной минимум 32 символа и `TELEGRAM_BOT_TOKEN` от @BotFather.
3. Выполните `npm run db:migrate`, затем `npm start`.
4. Укажите HTTPS URL приложения в настройках Telegram Mini App. Для внешнего фронтенда задайте его origin в `CORS_ORIGINS`.

`TELEGRAM_BOT_TOKEN`, `JWT_SECRET` и `AI_API_KEY` хранятся только в серверном `.env`; не публикуйте этот файл. Вход через Telegram проверяет HMAC-подпись и свежесть `initData` сервером. В обычном браузерном preview вход специально не подменяется фиктивной учётной записью.

## API, которое реализовано сейчас

Все перечисленные ниже API, кроме `/api/health` и `/api/auth/telegram`, требуют `Authorization: Bearer <token>` из Telegram-входа.

- `GET /api/health` — статус сервера/БД и наличие конфигурации (без секретов).
- `POST /api/auth/telegram` — проверка Telegram `initData`, создание/обновление пользователя и короткоживущей сессии.
- `GET /api/me`, `GET/PUT /api/profile`, `GET/PUT /api/settings`.
- `GET /api/music/tracks` — каталог с внешними страницами; аудио не копируется и не раздаётся приложением.
- `GET /api/empire/state`, `POST /api/empire/collect`, покупка территории и постройка здания. Баланс и транзакции вычисляются сервером в транзакциях PostgreSQL.
- Community: поиск пользователей, leaderboard, friends, отправка/принятие/отклонение заявок и удаление друга.
- AI: создание/просмотр/удаление диалога, загрузка истории и отправка сообщения через настроенный OpenAI-compatible API. Пока ключ и модель не настроены, endpoint честно отвечает 503, не симулируя ИИ.

## Что ещё не подключено

Существующий браузерный UI содержит локальные/демо-данные. Bridge включает Telegram SDK, получает сессию и предоставляет `window.DPApi`, но не переписывает и не подменяет все локальные модули. Чтобы профиль, экономика, друзья, плейлисты и AI использовали общую серверную БД, следующим этапом нужно перевести их существующие UI-обработчики на эти API и добавить отсутствующие CRUD-эндпоинты (например, редактирование плейлистов и полноценные friend request listings). Реальная работа с PostgreSQL требует настроенного сервера; облачная база и ключи провайдера не входят в репозиторий.

Дизайн не изменялся. Никакие внешние аудиоисточники не встраиваются автоматически: музыкальные записи ведут на исходные страницы.
